# Acceptance Criteria: Kanban Board

## Критерии приемки

- Пользователь видит канбан-доску как альтернативное представление задач.
- Задачи распределены по колонкам существующих статусов Task.
- Пользователь может переключаться между списком и доской.
- Смена статуса из доски обновляет ту же задачу `Task`, а не отдельную сущность.
- Существующий список задач не сломан и продолжает показывать актуальные данные.
- Тесты проходят.
- Docker-запуск не сломан, если Docker уже настроен в проекте.

## Основные сценарии проверки

1. Открыть экран задач.
2. Убедиться, что list view отображается и работает как в MVP.
3. Переключиться в board view.
4. Убедиться, что видны колонки статусов.
5. Убедиться, что задачи находятся в колонках согласно своим статусам.
6. Изменить статус задачи из board view.
7. Убедиться, что задача переместилась в колонку нового статуса.
8. Переключиться обратно в list view.
9. Убедиться, что та же задача отображается с новым статусом.
10. Обновить страницу и убедиться, что данные не рассинхронизировались.

## Негативные сценарии

- При ошибке загрузки задач board view показывает понятное состояние ошибки.
- При ошибке обновления статуса пользователь видит ошибку, а задача не остается в ложном успешном состоянии.
- Переключение между view не приводит к потере несохраненных изменений, если такие изменения существуют в текущем UI.
- Невалидный статус не может быть установлен через board view.

## Edge cases

- Нет задач: board view показывает пустые колонки или понятное пустое состояние.
- Все задачи находятся в одном статусе: остальные колонки остаются видимыми или корректно показывают пустое состояние.
- Длинные названия или описания задач не ломают карточки и колонки.
- Быстрое переключение list view / board view не приводит к дублированию задач.
- Mobile viewport сохраняет возможность просмотреть все колонки и карточки.

## Требования к тестам

- Frontend tests проверяют отображение board view.
- Frontend tests проверяют группировку задач по статусам.
- Frontend tests проверяют переключение между list view и board view.
- Frontend tests проверяют вызов обновления существующей Task при смене статуса.
- Backend tests добавлены или обновлены, если реализация требует backend-изменений.
- E2E smoke test покрывает основной сценарий переключения на доску и смены статуса.
- Regression tests подтверждают, что существующий список задач не сломан.

## Ручная проверка

- Проверить экран задач в desktop viewport.
- Проверить экран задач в mobile viewport.
- Проверить переключение между list view и board view.
- Проверить смену статуса минимум одной задачи из board view.
- Проверить, что list view отображает обновленный статус той же задачи.
- Проверить отсутствие отдельной сущности `KanbanTask` в коде, API и данных.
- Проверить Docker-запуск, если Docker доступен и уже настроен.

## Что считается готовым

- Канбан-доска доступна пользователю.
- Board view использует существующие задачи `Task`.
- Статусы задач корректно отображаются в колонках.
- Пользователь может переключаться между списком и доской.
- Смена статуса с доски сохраняется для той же задачи.
- Список задач продолжает работать без регрессий.
- Все релевантные тесты и проверки перед merge выполнены или явно описаны как недоступные с причиной.

## Что не проверяется в рамках фичи

- Настраиваемые пользователем колонки.
- Новая доменная сущность для канбана.
- AI-автоматизация задач на доске.
- Массовое редактирование задач.
- Производительность на больших объемах данных, если такие объемы не определены требованиями.
